# DSHD for Linux 0.2.2-rc.1.4

Packaging-only rebuild of the `0.2.2-rc.1.3` release. The upstream desktop
runtime is unchanged.

## What changed

- **Correct Linux application identity**: desktop files, `StartupWMClass` and
  icon names now consistently use `com.deepseek.harness`, matching the
  Electron app id.
- **Complete icon sets**: AppImage, deb, rpm and Flatpak now ship 16px through
  512px icons instead of only a single 1024px image. This fixes missing or
  mismatched icons in KDE menus, taskbars and window title bars.
- Applied the same app-id and icon rules to the AUR, OBS RPM, Snap and Nix
  packaging recipes.
- The previous `rc.1.3` package was installed and its welcome window launched on
  a physical Debian 13 (trixie) x86_64 / KDE Wayland host; this rebuild targets
  the icon regression found there.
- No changes to the bundled upstream runtime, providers or Office engine.

## Verification

```bash
gpg --import dshd-linux-release-signing.asc
gpg --fingerprint 2D4C2CFD4F1C3B5F8AF0DA481C9A912742C70369
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify deepseek-harness-*.AppImage \
  --repo openviewmobile/dshd-linux
```

For `v0.2.2-rc.1` only, import `deepseek-harness-release-signing.asc` instead.

## Why the filenames say "unsigned"

The `-unsigned` suffix is the upstream packaging mode used for Linux builds. It
means there is **no platform code-signing certificate** (Windows Authenticode or
macOS Developer ID/notarization). It does **not** mean the release is missing the
GPG trust chain:

- every file has a detached `.asc` signature;
- `SHA256SUMS` has `SHA256SUMS.asc`;
- `SBOM.spdx.json` is signed and included in the checksums;
- the APT/DNF repository metadata is signed with the production key.

## Known limitations

- The `rc.1.3` AppImage does not ship the LibreOfficeKit/WASM payload; Office
  conversion still depends on an available engine.
- AppImage auto-update has not completed a version-to-version acceptance.
- deb/rpm/Flatpak are not self-updating.
- Snap and OBS remain packaging artifacts, not Store/OBS service builds.
- Physical Wayland/KDE/GNOME and IME coverage remains limited.
- No platform code-signing certificate; GPG signatures are detached.
