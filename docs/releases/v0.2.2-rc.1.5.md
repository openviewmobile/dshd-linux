# DSHD for Linux 0.2.2-rc.1.5

Packaging-only rebuild of `0.2.2-rc.1.4`, focused on Linux desktop integration.
The upstream desktop runtime is unchanged.

## What changed

- **Title-bar icon**: the Electron welcome and main windows now set their native
  icon from `resources/icon.png` on Linux.
- **Desktop identity**: the desktop entry and `StartupWMClass` use
  `com.deepseek.harness`, matching the Electron app id.
- **Icon lookup**: the desktop entry uses the icon name that electron-builder
  actually installs, and all targets ship 16px through 512px icons.
- Applied the app-id and icon-size rules to the AUR, OBS RPM, Snap and Nix
  repackages.
- `rc.1.4` was installed on a physical Debian 13 (trixie) x86_64 / KDE Wayland
  host; this rebuild closes the remaining title-bar icon gap found there.
- No changes to the bundled upstream runtime, providers or Office engine.

## Verification

```bash
gpg --import dshd-linux-release-signing.asc
gpg --fingerprint 2D4C2CFD4F1C3B5F8AF0DA481C9A912742C70369
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify deepseek-harness-*.AppImage \
  --repo openviewmobile/dshd-linux
```

## Known limitations

- The AppImage does not ship the LibreOfficeKit/WASM payload; Office conversion
  still depends on an available engine.
- AppImage auto-update has not completed a version-to-version acceptance.
- deb/rpm/Flatpak are not self-updating.
- Snap and OBS remain packaging artifacts, not Store/OBS service builds.
- Physical Wayland/KDE/GNOME and IME coverage remains limited.
- No platform code-signing certificate; GPG signatures are detached.
