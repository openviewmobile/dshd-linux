# DSHD for Linux 0.2.2-rc.1.8

Packaging and repository validation release. The upstream desktop runtime is
unchanged.

## What changed

- **AppImage update configuration**: Linux release AppImages are unsigned, so
  electron-builder previously omitted `app-update.yml`. The generic update feed
  is now included when `DSHD_APPIMAGE_UPDATE_URL` is set. This release is the
  prerequisite for the first AppImage A→B acceptance.
- **RPM package signing**: repository publishing signs the RPM and verifies it
  with the imported public key; DNF installs with `gpgcheck=1`.
- **Arch repository**: pacman database and package signatures are published,
  and the Arch install smoke imports the release key and verifies the signed
  database.
- **Pages deployment**: pinned the Pages upload/deploy actions to v4 and wait
  for artifact indexing before deployment.
- **Gentoo**: sharp is rebuilt against the system libvips so Electron and sharp
  share one GLib; `~arm64` remains masked until the rebuild is verified.
- Repository install smoke passes for Debian 12 (APT), Fedora 41 (DNF) and
  Arch (pacman).

## Verification

```bash
gpg --import dshd-linux-release-signing.asc
gpg --fingerprint 2D4C2CFD4F1C3B5F8AF0DA481C9A912742C70369
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify deepseek-harness-*.AppImage \
  --repo openviewmobile/dshd-linux
```

## Known limitations

- This release contains the AppImage update configuration and is part of the A→B acceptance pair.
- The AppImage does not ship the LibreOfficeKit/WASM payload.
- deb/rpm/Flatpak are not self-updating.
- Snap and OBS remain packaging artifacts, not Store/OBS service builds.
- Physical Wayland/KDE/GNOME and IME coverage remains limited.
- No platform code-signing certificate; GPG signatures are detached.
